The transformer architecture has become the backbone of modern NLP — and increasingly of vision,
audio, and code tasks too. At its core sits the attention mechanism. Understanding it concretely,
not just conceptually, unlocks a lot of intuition about why transformers work so well.

## The Problem Attention Solves

Before transformers, sequence models used RNNs (or LSTMs). They processed tokens one at a time,
carrying a hidden state forward. The problem: by the time you reach token 200, the hidden state
has been squeezed through 199 update steps and has largely forgotten what token 1 said.

Attention breaks the sequential bottleneck. Every token can look directly at every other token
in one step.

## Scaled Dot-Product Attention

The operation is surprisingly compact. Given a sequence of tokens, we project each token into
three vectors: a **query** (Q), a **key** (K), and a **value** (V).

The attention output for a query is:

```
Attention(Q, K, V) = softmax(QK^T / sqrt(d_k)) V
```

What is this doing?

1. `QK^T` computes a similarity score between every query and every key — a dot product.
   High score means "this query is interested in this key."
2. Dividing by `sqrt(d_k)` prevents the scores from growing so large that softmax saturates
   (which would zero-out gradients and stop learning).
3. `softmax(...)` turns raw scores into a probability distribution over keys.
4. Multiplying by V produces a weighted sum of values — the tokens the model "attends to."

In Python with NumPy the core is three lines:

```python
import numpy as np

def attention(Q, K, V):
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)
    weights = np.exp(scores) / np.exp(scores).sum(axis=-1, keepdims=True)  # softmax
    return weights @ V
```

## Multi-Head Attention

Rather than one set of Q/K/V projections, transformers run `h` parallel attention heads, each
with its own learned projections. The outputs are concatenated and projected back down.

Why multiple heads? Each head can attend to different aspects of the input simultaneously — one
head might track syntactic agreement, another might track semantic similarity. Empirically this
helps significantly.

## Why This Replaced RNNs

Three practical reasons:

- **Parallelism**: All positions are computed simultaneously. No sequential dependency means
  modern GPUs (which are parallel machines) are fully utilized.
- **Long-range dependencies**: The path length between any two positions is O(1), not O(n).
  A token at position 1 can directly influence a token at position 512 in a single layer.
- **Interpretability**: Attention weights are auditable. You can visualize what the model
  attended to, which is harder with opaque RNN hidden states.

The tradeoff is memory: attention is O(n^2) in sequence length. This is why long-context models
require clever sparse or linear attention approximations — but that's a topic for another post.
