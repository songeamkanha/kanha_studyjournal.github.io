<objective>
Patch `DataManager.init()` with an `_initialized` guard flag so it is idempotent — safe to call any number of times without double-writing localStorage. This unblocks Phase 2 (content migration), which adds more call sites.

Purpose: INFRA-04 requires the double-init bug diagnosed and fixed before content migration begins. Currently, five call sites invoke `DataManager.init()` (four HTML files in `DOMContentLoaded` + one auto-call at script load time). Each call re-runs the init body, potentially overwriting localStorage state. The guard flag (D-08) is the minimal correct fix: two lines inserted at the top of `init()`, no HTML changes, no removal of the auto-call.

Output:

Target patch — insert two lines immediately after `init() {` opening brace,
before the first existing comment:
```js
init() {
  if (this._initialized) return;   // guard: prevent double-init
  this._initialized = true;        // mark as initialized
  // Initialize blog posts
  ...
```

Why `_initialized` works on an object literal (not a class):
  - `DataManager._initialized` is `undefined` on first call (falsy) — guard does not fire
  - After first call sets it to `true`, all subsequent calls hit `return` immediately
  - No constructor, no prototype modification needed
